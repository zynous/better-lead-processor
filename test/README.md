# Test folder

Local tests for the Lambda handler and LLM mapping: field name variations (camelCase, snake_case, etc.) and unmappable fields → note.

## Files

| File | Purpose |
|------|--------|
| `input-cases.json` | Input test cases: `id`, `description`, `input` (lead payload). Covers mapping (camel/snake, unmappable → note) and post-processing (invalid/empty email → note, partial address → Unknown, interaction → note). Cases with `skipForCrmFlow: true` are skipped by `run-llm-crm-tests.js`. |
| `expected-output.json` | Expected output per case (post-processed Better CRM shape). Used by `compare-outputs.js`. |
| `actual-output.json` | Generated by `run-mapping-tests.js`. Actual output (LLM + post-process) for each case. |
| `compare-outputs.js` | Compares `actual-output.json` to `expected-output.json` (per-case `output` vs `expected`). |
| `test-local.js` | Run Lambda handler locally (auth, LLM, Better CRM). Use "Debug Handler" in Run and Debug. |
| `run-mapping-tests.js` | Runs each input case through LLM mapper then post-process (no Lambda, no Better CRM) and writes `actual-output.json`. |
| `run-llm-crm-tests.js` | Runs each input case through full pipeline (Lambda: LLM → post-process → CRM). Probe-style output; expects 202 for all runnable cases. Writes `llm-crm-results.json`. |

## Prerequisites

- `pnpm build`
- `local-configs/app-config.json` and `local-configs/lice-squad.json`

## Run full handler (single event or one case)

From project root:

```bash
node test/test-local.js              # default event
node test/test-local.js minimal-camel   # case by id
node test/test-local.js 0               # case by index
```

Or: `pnpm run test:local` or `pnpm run test:local:case -- minimal-camel`.

## Run mapping tests (LLM + post-process)

From project root:

```bash
node test/run-mapping-tests.js
```

Runs each input case through the LLM mapper then post-process and writes `test/actual-output.json`. Or: `pnpm run test:mapping`.

## Compare actual vs expected

```bash
node test/compare-outputs.js
# or: pnpm run test:compare
```

Compares `actual-output.json` to `expected-output.json` (per-case `output` vs `expected`). `expected-output.json` should contain the expected **post-processed** output. Update it after reviewing actual output to catch regressions later.

## CRM Lead API probe (discover mandatory/optional and validation)

The probe calls the **Better CRM Lead API** directly with many payload combinations (single fields, combinations, address partial/full, invalid email, etc.) to see what the API accepts vs rejects. Use this to document how the CRM actually behaves (which may differ from API docs) and to define the final working set for post-processing.

**Prerequisites:** Same as above (`local-configs/app-config.json` and a franchisor config with franchise credentials).

From project root:

```bash
pnpm run test:crm-probe
# or: node test/crm-api-probe.js
```

Optional:

```bash
node test/crm-api-probe.js --case=first-name-only   # run one case by id
node test/crm-api-probe.js --case=0                 # run one case by index (0-based)
node test/crm-api-probe.js --franchisor=lice-squad --franchise="Franchise Name"
node test/crm-api-probe.js --dry-run   # list cases only, no API calls
```

**Output:**

- `test/crm-api-probe-results.json` — per-case HTTP status, body code, success flag, and API error message.
- Fill in `test/CRM-API-FINDINGS.md` from the results to record: minimum required identity fields, email validation, address rules (omit vs partial vs full), and the final working set for the Lead API.

## Full LLM → CRM flow (post-processing verification)

Runs each input case through the **full pipeline** (Lambda handler: LLM map → post-process → Better CRM). Use this to verify that post-processing fixes (invalid email → note, partial address → Unknown, interaction → note, etc.) result in CRM 201 for all runnable cases. Output style matches the CRM probe (✅/❌ per case, then summary).

**Prerequisites:** Same as above. In addition, the LLM needs credentials (e.g. `openai_api_key` in `app-config.json` or `OPENAI_API_KEY` in the environment), and the default path uses franchise `barrie` — ensure `lice-squad.json` has a franchise named `barrie` with valid API key and CRM credentials.

From project root:

```bash
pnpm run test:llm-crm
# or: node test/run-llm-crm-tests.js
```

Optional:

```bash
node test/run-llm-crm-tests.js --case=postprocess-invalid-email   # run one case by id
node test/run-llm-crm-tests.js --case=0                           # run one case by index (0-based)
node test/run-llm-crm-tests.js --dry-run                          # list cases to run, no API calls
```

**Output:**

- Console: one line per case (`✅ id → 202` or `❌ id → status | message`), then `Summary: X passed, Y failed`.
- `test/llm-crm-results.json` — run timestamp, passed/failed counts, and per-case status and message.
- Exit code 1 if any case failed.
